代理式 AI:架構、評估與生產維運

從多代理架構到生產維運 — 用治理框架讓 agentic AI 既能自主又可信賴。
學習目標： 多代理模式 · 自主權 vs. 控制框架 · 生成後評估 · 生產維運與失效模式

1

重點概念

Key Concepts · Multi-Agent → Autonomy → Evaluation → Production
🧩
01

多代理分解

Multi-Agent Decomposition

當工作需要不同技能、各階段可獨立測試、失敗模式彼此分離時,就該拆成多個專職 agent,用品質關卡隔離故障。

Telecom BSS Magic 用 5 個專職 agent 把變更請求處理時間從 7 天縮短到數小時
⚖️
02

自主權光譜

Autonomy Spectrum

自主程度是從 Factory Floor(人工逐步把關)到 Trading Floor(即時授權、硬限制)的連續光譜,分層自主依風險分配監督才是可行解。

Mortgage Guardian 讓一般再融資案件自動處理,複雜或規管灰色案件才升級給人工
❓
03

三問測試

Three-Question Test

用後果嚴重度、可偵測性、可逆性三個問題判斷自主權高低,三者皆低風險才給完全自主,任一項高風險就加人工監督。

錯誤商品推薦可全自動;錯誤用藥劑量需人在迴圈每一步把關
⚠️
04

不對稱風險校準

Asymmetric Risk Calibration

假陽性與假陰性的代價常不對等,系統校準應優先壓低代價較高的錯誤類型,即使因此容忍更多低代價錯誤。

法規遵循情境中,漏抓真正違規遠比誤判合規通話嚴重
🔁
05

生成後評估模式

Generate-Then-Evaluate

生成與評估該由不同模型分開執行,中間設品質關卡,做到專業分工、生產前攔截錯誤、並讓失敗案例帶著具體回饋自動重生。

汽車行銷圖由 diffusion model 生成,Amazon Bedrock 上的 VLM 依品牌規範把關
🛡️
06

評估者獨立性

Evaluator Independence

評估者穩健度分三級:同模型自我反思最弱,換一個不同模型評估較強,無模型涉入的確定性計算最穩健,風險越高就該選越穩健的一級。

房貸試算用獨立的數學函式驗算省息金額,和 Claude 算出的數字互相比對
💰
07

成本是風險降低

Cost as Risk Reduction

加評估步驟會讓單位成本上升,但比人工審查便宜八到九成以上,且能把流入生產的錯誤比例壓到百分之一以下,對 CFO 應以風險降低而非成本增加來框定。

用兩分錢的評估成本防範一次五千元的補救事故
📉
08

模型漂移

Model Drift

AI 系統即使程式碼不變,也會隨真實世界改變而退化,常見型態有資料漂移、校準漂移與人口結構漂移,必須定期偵測並訂出重新校準節奏。

Fashion Agent 的商品嵌入沒跟上新品上架,導致搜尋相關度與點擊率下滑
⚙️
09

生產維運四支柱

Production Operations

上線只是起點,監控與可觀測性、漂移偵測與補救、成本優化、稽核留痕四項維運工作,決定系統能持續產生價值還是逐漸退化。

Prompt Caching、模型分級、批次推論與用量計費是四種常見的成本優化手法
📋
10

稽核留痕

Audit Trails

稽核紀錄讓系統事後能證明做了什麼、為何這樣做、用了什麼資料,同時服務法規遵循、問題除錯與治理三種需求。

AWS CloudTrail 記錄 API 呼叫,S3 存取日誌記錄資料讀寫,應用程式日誌記錄模型版本與信心分數
🚨
11

Agentic 失效模式

Agentic Failure Modes

多代理系統的風險會疊加,包括幻覺數字、外部 API 回傳過期或錯誤資料、錯誤逐階放大、角色逾權與成本失控迴圈,每一種都需要對應的硬限制護欄。

房貸 agent 用時間戳驗證利率資料、提示詞限制只能分析不能下指令、重試與 token 上限搭配斷路器
🛑
12

拒絕並升級設計

Refuse-and-Escalate

知道何時該停下交給人工,和知道怎麼繼續執行一樣重要,財務困境、法律複雜、競業比價、詐欺疑慮或超過複雜度門檻都該被明確設計為立即升級的觸發點。

✓

隨堂測驗考點

Knowledge Checks
Knowledge Check 1
什麼時候該把一個 agent 拆成多個專職 agent?
✓

當不同階段需要不同技能、可獨立測試、且失敗模式彼此分離時,才該拆成多代理管線,用品質關卡隔離故障。

Knowledge Check 2
分層自主(Tiered Autonomy)背後的核心判斷依據是什麼?
✓

後果嚴重度、可偵測性、可逆性三問測試:三者皆低風險才給完全自主,任一項高風險就加人工監督。

Knowledge Check 3
為什麼評估者不能是生成內容的同一個模型?
✓

因為同模型自評會共享相同盲點,獨立性越強(換模型、甚至用確定性計算)評估關卡才越可靠。

Knowledge Check 4
為什麼 AI 系統即使不改程式碼也會變差?
✓

因為 AI 是機率性且依賴模型與真實世界資料的關係,世界改變(資料、校準基準、服務對象)而模型沒跟上,品質就會悄悄退化,這就是模型漂移。

Knowledge Check 5
面對 CFO 質疑評估步驟的額外成本,策略者該怎麼框定?
✓

把它框為風險降低而非成本增加:用遠低於補救成本的評估支出,防範高成本的生產事故。

Knowledge Check 6
為什麼『拒絕並升級』的設計和『如何執行』一樣重要?
✓

因為自主權必須有明確邊界,財務困境、法律複雜、競業比價、詐欺疑慮等情境必須被設計成觸發立即升級,而非等出事才發現系統不知道要停。

⭐

一句話總結

把自主權光譜、生成後評估、與生產維運三者整合進治理設計,才能讓 agentic AI 在規模化時依然可信賴、可持續。
