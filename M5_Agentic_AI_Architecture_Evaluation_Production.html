代理式 AI：架構、評估與正式環境維運

從多代理架構到正式環境維運 —— 用自主權框架與生成評估模式，打造禁得起正式環境考驗的 Agentic AI。
學習目標： 多代理分工模式 · 自主權 vs 控制框架 · Generate-then-Evaluate 模式 · 正式環境維運與模型漂移 · 失效模式與護欄設計

1

重點概念

Key Concepts · Multi-Agent → Autonomy → Evaluate → Operate
🧩
01

多代理分工

Multi-Agent Decomposition

當工作流程各階段需要不同技能、可獨立測試、且失效模式可彼此隔離時，才把任務拆給多個專責代理，而不是想辦法讓單一代理做得更快。

Telecom BSS Magic：分析師→架構師→開發→QA→測試 五代理管線，7 天縮短為數小時
⚖️
02

自主權光譜

Autonomy Spectrum

自主權不是二元選擇而是光譜；「工廠模式」在每個步驟前先讓人把關，適合偏差危險、速度非首要的情境，「交易大廳模式」只在觸及硬限制時才介入，適合速度為王的情境，兩者差別只在人「何時」介入。

Fintech 房貸代理：例行案件自主執行，複雜案件才交給 Escalation Agent
❓
03

三問測試

The Three-Question Test

用「後果多嚴重、能否在造成傷害前偵測到、動作能否復原」三個問題評估每項代理能力該給多少自主權：三項皆低風險就給完全自主，任一項高風險就在該環節加人工監督。

產品推薦錯誤（低風險，可自主）vs 用藥劑量錯誤（高風險，需人審）
🎚️
04

分層自主

Tiered Autonomy in Practice

把「例行、低風險」交給代理自主執行，「複雜、模糊、高風險」升級給人類審查，分層邊界要在設計階段就先劃定，而不是等正式環境出包才發現。

Fashion Agent／Mortgage Guardian／Pharmacy Agent 皆採自主層＋人工升級層的相同模式
🔀
05

生成後評估

Generate-then-Evaluate

高風險生成內容要把「生成」與「評估」拆成兩個獨立步驟、用不同模型或機制，因為生成模型追求品質、評估模型追求合規，兩者目標不同，合一反而兩頭皆差。

汽車廠：微調擴散模型生成車輛圖像 → Bedrock 上的 VLM 依品牌規範評分 → 不合格則帶著具體回饋重新生成
🛡️
06

評估者獨立性

Evaluator Independence

評估者的獨立程度要對應風險高低：同模型「自我反思」最弱、換一個「獨立模型」評估較穩健、用「確定性邏輯」檢查最強且不會產生幻覺；風險越高、人工複查越少，就需要越強的獨立性。

航運情報用自我反思（有人複查）；房貸試算改用獨立數學函式驗證省息金額
💰
07

成本＝風險降低

Cost as Risk Reduction, Not Addition

評估步驟雖讓單位成本多出約四成，但比人工審查便宜近九成；面對財務主管質疑時，要把評估支出重新框架成「用幾分錢防範數千元的補救成本」，而不是單純的費用增加。

生成＋評估每張圖約 $0.0575，對比人工審查每張 $0.50–0.83（便宜 87–93%）
📉
08

模型漂移

Model Drift

AI 系統即使程式碼完全不變，也會因為世界改變而品質下滑（資料漂移、校準漂移、人口結構漂移），必須建立偵測指標與依風險排定的複檢週期，不能假設「部署後就永久不變」。

Fashion Agent 商品向量未更新使搜尋相關度下滑；房貸門檻未隨利率調整而推薦不划算的轉貸
👁️
09

行為可觀測性

Behavioral Observability

傳統監控只回答「系統有沒有在跑、延遲多少、錯誤率多少」，代理式 AI 還需要多一層「推理層級」的觀測——判斷是否在退化、決策模式是否改變，才能真正回答「這個代理值不值得信任」。

延遲與錯誤率全部正常，但推薦內容已經逐漸離題或不準確
🧾
10

稽核軌跡

Audit Trails

稽核軌跡同時服務合規（證明審查依據）、除錯（重建決策鏈）與治理（問責歸屬）三種需求，靠 CloudTrail 記錄 API 呼叫、S3 存取日誌記錄資料存取、應用層日誌記錄模型版本與信心分數來落地。

藥局福利管理商的處方預審核決策，必須可追溯每一步判斷依據
🚨
11

失效模式與護欄

Failure Modes & Guardrails

代理式系統的風險會疊加：幻覺數字、外部 API 資料錯誤、多步驟誤差累積、越權建議、失控重試造成的成本暴衝；對應護欄分別是確定性數值驗證、時間戳與多來源比對、重試上限與斷路器、輸出過濾，以及明確定義「拒絕並升級」的觸發情境。

24/7 房貸代理案例：幻覺月省金額、隔夜過期利率、鑑價高估、越權建議「你應該現在轉貸」、API 無限重試導致費用暴衝
✓

隨堂測驗考點

Knowledge Checks
Knowledge Check 1
什麼訊號告訴你該把單一代理拆成多代理架構？
✓

當每個階段需要不同技能、可獨立測試、且失效模式可被隔離三個訊號同時出現，就該拆解成多代理管線；否則一個環節出錯就會拖垮全部。

Knowledge Check 2
三問測試中，若「後果、可偵測性、可逆性」三項都是低風險，該給代理多少自主權？
✓

可以給予完全自主；只要任一項是高風險，就要在那個環節加上人工監督或審查。

Knowledge Check 3
評估者獨立性的三種形式裡，哪一種最穩健？為什麼？
✓

確定性（deterministic）邏輯檢查最穩健，因為它不是模型、不會產生幻覺，也不會和生成模型共享同樣的推理盲點；同模型的「自我反思」則最弱。

Knowledge Check 4
為什麼「生成＋評估」比只做生成貴，卻仍然值得？
✓

雖然單位成本增加約 44%，但比人工審查便宜 87–93%，而且能在錯誤進入正式環境前攔截——應把它框架成「風險降低」而非「額外支出」。

Knowledge Check 5
AI 系統為什麼會在完全沒改程式碼的情況下品質下降？
✓

因為 AI 是機率性的，品質取決於模型與現實世界資料之間的關係；世界改變（新商品、利率變動、使用族群變化）會讓模型逐漸「漂移」，必須定期偵測與補救。

Knowledge Check 6
為什麼「拒絕並升級」的設計和「執行」的設計同等重要？
✓

因為知道何時該停下來交給人類（財務困境、法律複雜案件、競爭性報價、詐欺跡象、超過風險門檻）本身就是必要的設計決策，不能等出包才臨時補上。

⭐

一句話總結

自主權要依「後果、可偵測性、可逆性」分層、評估必須與生成獨立，而正式環境維運（監控、漂移、成本、稽核）從設計第一天就該算進 ROI，而非等出問題才補救。
