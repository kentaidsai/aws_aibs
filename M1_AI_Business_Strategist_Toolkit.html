重點概念

Key Concepts · Role → Strategy Layer → 3D Framework → Tech Foundations

01

策略顧問的角色缺口

The Gap

策略顧問填補組織「我們想要 AI」與「具體可執行方案」之間的落差,核心能力是翻譯,不是建造模型。

技術團隊想模型、業務想成本、法務想風險——三方各自為政時,策略顧問是連接點
👂
02

心態：先傾聽,再設計

Listen Before You Design

策略顧問最重要的技能不是技術知識,而是在提出方案前,保持夠久的傾聽與提問紀律。

資料科學家造引擎、工程師造車,策略顧問決定要造的是「車」而不是船或飛機
🏛️
03

企業策略層五大構面

Enterprise Strategy Layer

AI Vision 定義終點、Roadmap 排序路徑、Portfolio 決定投資取捨、Governance 設護欄、CxO Engagement 貫穿全程提供贊助。

AI Vision 範例:「三年內成為同業中最懂顧客個人化的零售品牌」
🚦
04

投資組合決策：擴大/暫停/終止

Scale, Pause, Terminate

依 Business Value、Feasibility、Strategic Alignment、Risk 四維度評分,指標達標則擴大、結果不明則暫停、指標未達則終止,三者同等正當。

終止決策必須和啟動決策一樣講證據,而非因沉沒成本而無限期延長
🧭
05

3D 框架總覽

Discover-Design-Deliver

3D 框架以九個步驟串連 Discover(診斷問題、評估整備度、確認資料品質)、Design(對應能力、納入治理、界定 POC)、Deliver(建置驗證、試點導入、擴展企業平台),是策略顧問每天使用的執行方法。

Roadmap 決定「下一步做哪個節點」,3D 框架決定「怎麼執行那個節點」
🚪
06

守門文件：對齊才能往下走

Gate Documents

Discovery Readout 與 Final Report 等正式文件,強迫業務、技術、法遵等利害關係人在進入下一階段前取得共識,避免還沒對齊就先動工。

Launch Gate 卡在 POC 與試點之間,決定「迭代或終止」;Scale Gate 卡在試點與企業部署之間
🪆
07

AI、ML、GenAI 的巢狀關係

AI ⊃ ML ⊃ GenAI

傳統 AI 由人寫規則、ML 讓系統從資料學規則、GenAI 則產生全新內容;GenAI 是工具箱裡的新增項,不是取代傳統 AI/ML 的方案。

詐欺偵測用傳統 ML、通話摘要用 GenAI、核准流程用規則式自動化——選錯類型就是問題分析失誤
🧠
08

Foundation Model 類型與來源

LLM / VLM / Multimodal · 1P/3P/OSS

依輸入輸出型態分為 LLM、VLM、Multimodal 三類,再依來源分為 AWS 自建(1P)、經 Bedrock 引入的第三方(3P),以及經 SageMaker 自行託管的開源模型,各自對應不同的整合、能力與控制權取捨。

LLM 用 Claude on Bedrock;VLM 用於工地設備辨識;開源模型透過 SageMaker 微調
🔄
09

GenAI 五步驟資料流與核心服務

Data Flow & AWS Services

幾乎所有 GenAI 架構都遵循 來源 → 儲存(S3) → 處理(Lambda/Step Functions) → 模型(Bedrock/SageMaker) → 輸出 的五步驟,資料品質是比模型選擇更常見的失敗原因。

Garbage in, garbage out——影像解析度不一致會讓向量嵌入與搜尋結果一併失真
🪜
10

模型調適的升級階梯

Prompt → RAG → Fine-tune → Agent

調適一律先從提示工程開始,需要專屬資料再加 RAG,需要學習領域模式才微調,需要動態多步驟工具協作才用 Agent,複雜度與成本依序遞增。

單靠提示工程優化,分類準確率就從 34% 提升到 70%,零訓練成本
🤖
11

Agent 與自主權 vs. 控制

Autonomy vs. Control

Agent 能自主推理、選擇工具、執行多步驟並依結果調整,與單步驟的模型呼叫/RAG/固定流程不同;自主程度應依失敗後果、可偵測性與可逆性分級授權。

Amazon Bedrock AgentCore 提供 Runtime、Memory、Gateway、Identity、Observability 等服務,協助 Agent 從原型走向生產

隨堂測驗考點

Knowledge Checks
Knowledge Check 1
當 VP 說「商品探索功能壞了」,這句話算是 AI Vision 還是症狀?為什麼策略顧問不能直接拿它當作專案範疇?
✓

這是症狀 (symptom),不是範疇;策略顧問必須先探詢「壞掉的樣子」,把模糊抱怨轉換成有邊界、可衡量的問題陳述。

Knowledge Check 2
一個試點沒有達成成功指標時,為什麼「終止」必須和「啟動」用一樣嚴謹的證據基礎來決定?
✓

因為終止決策必須證據導向,而非基於沉沒成本或害怕對話而無限期延長;Scale、Pause、Terminate 三個結果都是同等正當的策略選擇。

Knowledge Check 3
Roadmap 的「Phase 2:Capability Building」為什麼不能跳過?
✓

因為缺少基礎設施、資料管線、治理框架與人才技能,組織直接從 Quick Win 跳到企業部署幾乎必定失敗;Roadmap 決定做哪個節點,3D 框架決定怎麼做。

Knowledge Check 4
為什麼「詐欺偵測」該用傳統 ML 而不是生成式 AI?
✓

因為這是分類/預測任務,傳統分類器表現更好;不是每個問題都需要 GenAI,策略顧問的工作是把解法配對到問題本質。

Knowledge Check 5
模型調適的決策順序是什麼,為什麼要「一律」先用提示工程?
✓

一律先從提示工程開始,因為零成本、零訓練就能大幅提升效果;只有需要專屬資料才加 RAG,需要學習領域模式才微調,需要動態多步驟工具使用才用 Agent。

Knowledge Check 6
判斷一個 Agent 該被授予多少自主權的三個問題是什麼?
✓

(1) 出錯的最壞結果是什麼 (2) 使用者能否在造成傷害前發現錯誤 (3) 錯誤是否可逆;後果輕微、可偵測、可逆→高自主;後果嚴重、難偵測、不可逆→需人工監督。

⭐

一句話總結

AI Business Strategist 的核心價值在於翻譯與連結——把模糊的企業雄心,轉換成在企業策略層指引下、透過 3D 框架 (Discover-Design-Deliver) 執行的具體且可問責的技術方案。
