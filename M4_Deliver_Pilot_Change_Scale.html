1

重點概念

Key Concepts · Build → Calibrate → Evaluate → Deploy → Scale
🧪
01

POC 與 Pilot 分工明確

POC vs. Pilot

POC 在內部用 representative data 與 calibration cohort 驗證能力，Pilot 才對真實顧客做 bounded deployment，兩者的風險與產出完全不同。

POC 產生 evidence，Pilot 才產生 conversion lift 等 business outcome
📋
02

計畫與證據互相檢核

Plan vs. Evidence Gate

Section 6 的 POC Scope Document 訂出 threshold，Section 7 的 POC Results Pack 回報是否達標，兩者形成 explicit check，讓落差成為「事實」而非各自表述。

沒達標＝交給 stakeholder 決策，不能硬拗成 directionally positive
🎯
03

校準是 POC 的招牌活動

Calibration: One Event, Two Outcomes

由 strategist 與資深 merchandiser 設計約 100 題涵蓋 easy／hard／edge case 的 query set，讓評分者獨立評分產生 agreement rate，同一場校準同時產出 Section 7 的證據與 Section 8 的信任基礎。

「AI 比你厲害嗎」引發抗拒；「需要你的專業來驗證」才能換來真心投入
🔧
04

三個迭代槓桿

Three Iteration Levers

Prompt versioning、RAG ablation（embedding 維度／top-k／similarity threshold）、confidence threshold experiment 都要對同一份 calibration query set 測試，結果才具可比性。

agent 對海灘婚禮推薦太正式的洋裝 → 調整 system prompt 後重跑同一組 query
💎
05

四維度同時評分，不能分開看

Performance · Fairness · Safety · Trust

Performance 由 engineering 負責，Fairness／Safety／Trust 由 strategist 守門，任一維度落後都等於整體評估失敗，高效能但低信任的系統會被使用者默默 override。

Safety+Trust 缺口 → 系統被「用到沒人用」
📈
06

信心門檻用資料算出來

Empirical Confidence Threshold

把 confidence score 對 merchandiser agreement rate 畫成 S 曲線，找到約 95% 一致率的那一點設為 production threshold，風險越高的能力（如 inpainting）門檻要設得越高。

視覺搜尋門檻較低；圖像生成、inpainting 門檻最高
📦
07

POC 成果包是決策文件

POC Results Pack

內容涵蓋四維度 scorecard、校準數據摘要、門檻建議與已知限制，最終給出明確的 launch／decline 建議，刻意排除行銷語言與模糊字眼。

四選一：Launch as scoped／Launch with modifications／Defer／Do not launch
🪜
08

漸進式自主權三階段

Shadow → Supervised → Monitored

Agent 的自主權要靠 override rate、escalation quality 等指標門檻逐步解鎖，不是時間到了就升級，且每一階都保留立即 rollback 的能力。

Shadow 轉 Supervised 的 gate：override rate 低於 15%
🔄
09

回饋迴圈是門檻的證據引擎

The Feedback Loop

Agent 建議 → 使用者接受／修改／拒絕 → 結構化紀錄 → 系統改善 prompt／RAG／threshold，形成 virtuous cycle，回饋摩擦力要夠低才有量、夠結構才能用。

implicit override（低摩擦高量）／structured 讚踩（高信號）／qualitative 文字回饋（最豐富最耗神）
🌟
10

找 Champion 看可信度，不看熱情

Champions: Credibility over Enthusiasm

校準時挑出最敢質疑、最誠實指出弱點的人當 champion，給他們已知限制清單與批評的許可，再靠同儕影響力而非高層命令來推廣，且絕不公開宣布。

校準時問最刁鑽問題的資深 merchandiser，比一味稱讚的人更適合當 champion
📊
11

行為指標勝過虛榮指標

Behavioral over Vanity Metrics

登入次數、使用時長、滿意度分數會騙人——人們口頭喜歡卻可能默默 override；真正能預測擴大成功的是 override rate 下降、time-to-first-action 縮短、unprompted usage 與 peer 推薦率。

滿意度調查最容易踩坑：「說喜歡，但還是自己選」
🏛️
12

分階段流量遷移＋CoE 防止退化

Phased Rollout & Center of Excellence

從舊系統遷移採 5%→20%→50%→100% 分階段，每個 gate 都保留立即 rollback；上線後交給小型 AI CoE 負責 weekly／monthly／quarterly 的 re-ingestion 與稽核，否則 pilot 成功後系統會因無人維護而悄悄失能。

「AI 沒用」常常是 ownership 失敗，不是技術失敗
✓

隨堂測驗考點

Knowledge Checks
Knowledge Check 1
POC 沒有達到預定 threshold，團隊仍想直接上線 Pilot，為什麼不建議？
✓

因為 threshold 是 Section 6 就訂好的事實檢核，沒達標就是一個「事實」，該交給 stakeholder 決策，而不是用「directionally positive」硬拗上線。

Knowledge Check 2
為什麼校準要用 merchandiser 當 ground truth，而不是讓工程團隊自己評分？
✓

因為 engineering 不能代表真實顧客會怎麼問、怎麼判斷，query set 與評分必須由 strategist 與 merchandiser 設計，才能反映顧客觀點。

Knowledge Check 3
一個系統 Performance 和 Safety 分數都很高，但 Trust 很低，能不能直接上 Pilot？
✓

不行——四個維度必須同時達標；Trust 偏低代表「高效能＋低信任＝還沒準備好上 pilot」，使用者會表面同意、實際上默默 override。

Knowledge Check 4
校準評分時，為什麼要讓 merchandiser 在打分數前先看不到 agent 的 confidence score？
✓

為了避免 anchoring bias（錨定效應）——先讓評分者獨立判斷，才能得到乾淨的 agreement rate 作為信任指標。

Knowledge Check 5
Graduated autonomy 從 Shadow 進到 Supervised 的依據是什麼？
✓

證據門檻達標，不是時間到——例如 override rate 必須降到 15% 以下才能晉級，滿 4 週但指標沒過還是不能升級。

Knowledge Check 6
為什麼滿意度調查（satisfaction survey）被歸類為 vanity metric？
✓

因為使用者常常口頭說喜歡，行為上卻仍默默 override；真正該看的是 override rate 趨勢、time-to-first-action、unprompted usage 等行為指標。

⭐

一句話總結

本模組的核心是「用證據治理每一步」：POC 靠校準數據證明系統堪用、Pilot 靠行為指標證明使用者真的信任、Scale 則靠 CoE 與回饋迴圈把一次性專案變成能持續自我改善的企業平台。
